# Відповіді 

1. **Яким видом підзапиту (скалярний, табличний, корельований, похідна таблиця) ви скористалися і чому саме ним?**

Для розв'язання задачі використано **загальні табличні вирази (CTE / СТЕ)** за допомогою конструкції `WITH` (зокрема, табличні підзапити):
* **`cat_sales`** — табличний СТЕ, який групує та обчислює суму куплених одиниць (`taken`) для кожної категорії.
* **`total_sales`** — скалярний/похідний СТЕ, який обчислює загальну суму продажів по всіх категоріях разом (`total`).

Використання двох блоків `WITH` дозволяє розбити складний покроковий розрахунок на чіткі, зрозумілі логічні етапи (спочатку локальна агрегація категорій, потім обчислення загального підсумку, і наприкінці — розрахунок відсоткової частки `share`). Це робить SQL-запит легкочитаним зверху вниз та уникає дублювання агрегатних обчислень.

2. **Чи можна записати вашу задачу без підзапиту і що зміниться?**

Формально записати запит без підзапитів або СТЕ можна, але це істотно змінить підхід:
1. **Через віконні функції:** Можна було б використати віконну функцію `SUM(SUM(p.quantity)) OVER()`, проте використання віконних функцій у цій практичній роботі явно заборонено умовами (це тема наступної роботи OBDZ-P07).
2. **Без віконних функцій і без СТЕ:** Довелося б робити вкладений підзапит безпосередньо в списку `SELECT` або у секції `FROM`, наприклад: `ROUND(100.0 * SUM(p.quantity) / (SELECT SUM(quantity) FROM purchase), 1)`. 

Отже, без використання підзапиту/агрегації вищого рівня обчислити відсоткову частку кожної категорії від загальної суми в одному стандартному `GROUP BY` **неможливо**, оскільки для розрахунку знаменника потрібен підсумок по всіх категоріях одразу.

3. **Що станеться з вашим запитом, якщо в підзапиті з'явиться NULL або порожній результат?**

* **Порожній результат:** Якщо в таблиці `purchase` немає жодного запису про покупки, СТЕ `cat_sales` повернутиме порожню множину (0 рядків). Відповідно, `total_sales` поверне `NULL` для `SUM(taken)`. Підсумковий `CROSS JOIN` поверне порожній результат (0 рядків), що повністю відповідає умові «категорії без покупок не виводити».
* **Наявність `NULL` у даних:** Оскільки агрегатна функція `SUM()` в PostgreSQL ігнорує значення `NULL`, наявність `NULL` у кількостях не призведе до помилки. Використання внутрішніх з'єднань (`JOIN`) гарантує, що у вибірку потраплять лише ті категорії, які дійсно мають пов'язані товари та покупки.
